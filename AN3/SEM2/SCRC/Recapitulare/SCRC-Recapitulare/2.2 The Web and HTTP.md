## 1. Baza: Obiecte și proprietatea ”Stateless”

- o pagină web este compusă din obiecte (un fișier de bază HTML + poze, scripturi, etc), fiecare fiind identificat de un URL (hostname + path).
- HTTP folosește **TCP pe portul 80** pentru a garanta transferul corect al datelor.
- HTTP este un protocol **Stateless** (fără stare). Asta înseamnă că serverul nu reține absolut nicio informație despre cererile trecute ale aceluiași client, ceea ce simplifică masiv designul serverelor.

---

## 2. Conexiuni: Persistent vs Non-Persistent

#### Non-Persistent (HTTP/1.0):
- Pentru un fișier HTML + 10 JPEG:
	1. Se inițializează o conexiune nouă TCP.
	2. Send HTTP Request
	3. Server Responds
	4. Client parses HTML
	5. Repeat x 10
- Practic pentru fiecare fișier se parcurg acești cinci pași.

#### Persistent cu Pipelining (HTTP/1.1)
- Server-ul lasă conexiunea TCP deschisă, astfel că toate obiectele de pe același server împart o singură conexiune.
- Prin *pipelining* clientul poate trimite cererile una dupa alta, reducând timpul total la aproximativ 1-2 RTT-uri.

## 3. Mesaje și Coduri de Status

- **Metode în Request:**
	- **GET:** cere un obiect.
	- **POST:** Trimite date către server.
	- **HEAD:** Cere de la server doar headerele, fără obiectul în sine.

- **Coduri de status HTTP:**
	- **200 OK:** totul a decurs cu succes.
	- **301 Moved Permanently:** URL-ul s-a schimbat, browser-ul face redirect automat.
	- **304 Not Modified:** Spune că obiectul din memoria cache este încă valabil, deci server-ul trimite doar acest header, fără obiectul propriu-zis salvând bandă.
	- **400 Bad Request / 404 Not Found:** Erori generale sau obiecte inexistent.

## 4. Cookie-uri
- deoarece HTTP-ul este stateles, site-urile folosesc Cookie-uri pentru a ține minte (ex. coșul de cumpărături).
- Implică 4 elemente:
	1. **Header-ul Ser-cookie:** trimis de server la prima vizită.
	2. **Header-ul Cookie:** pe care browser-ul tău îl trimite automat la fiecare cerere ulterioară.
	3. **Fișierul cu cookie-uri de pe PC-ul tău.**
	4. Baza de date din spate a serverului care mapează ID-ul tău cu acțiunile tale.

## 5. Web Caching (Proxy Servers) și Conditional GET

- Un Web Cache acționează simultan ca **un server pentru tine** și ca **un client pentru serverul propriu-zis**.
- Astfel un mare beneficiu, este scăderea timpului de răspuns, dar mai ales reduce treficul pe link-ul de acces la internet al unei instituții, salvând costuri majore.

- **Conditional GET:** Pentru a nu da utilizatorului un obiect învechit, cache-ul întreabă server-ul de fiecare dacă s-a modificat fișierul iar dacă este la fel, server-ul răspunde cu **304 Not Modified**, iar cache-ul știe că poate folosi copia sa.

## 6. HTTP/2 și HOL Blocking

- **Problema (HOL Blocking):** În HTTP/1.1 (folosind o singură conexiune), dacă un obiect mare (un video) se trimite primul, toate imaginile mici stau blocate la coadă după el (Head-of-Line Blocking)
- **Soluția HTTP/2:** Sparge mesajele în "frame-uri" mici de date ("framing") și le interclasează pe o singură conexiune TCP, astfel încât imaginile mici să treacă printre bucățile din video. De asemenea, introduce **Server Push** (serverul îți trimite obiecte înainte să le ceri) și prioritizare
